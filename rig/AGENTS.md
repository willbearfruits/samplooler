# Samplooler Rig: commands

Generated by `slrig agents-md` from the registry. Every command answers `{"ok": true, "result": ...}` or
`{"ok": false, "error": {"code", "message", "hint"}}`. The viewer, the CLI (`slrig run CMD k=v ...`), OSC
and the MCP server (`rig_run`) all run these.

## audio

### `audio.devices`

The board's PipeWire nodes (its USB sound card: what it plays to the computer, what the computer plays in).

### `audio.measure` (slow)

Listen to the board over USB for a while and measure: levels, noise floor, clicks, bad samples, and with a known tone in the loop, the real playback speed over time. On the twin, its own output is measured.

| argument | type | default | what |
|---|---|---|---|
| `secs` | number | 3.0 | how long. |
| `tone_hz` | number | 0.0 | the frequency of the tone recorded as the take (0: no speed measurement). |

## board

### `boards`

The Samplooler boards on USB (a TWOFOLD is never listed).

### `connect`

Open the Samplooler on USB (found by its MIDI port's name, never a TWOFOLD), or start the twin when there is none (or when asked).

| argument | type | default | what |
|---|---|---|---|
| `source` | string | 'auto' | auto: a board if one is plugged in, else the twin; board: a board or an error; twin: the twin. |
| `serial` | string | '' | part of the board's USB serial when more than one is plugged in. |
| `scene` | string | 'still' | the twin's motion when nothing is injected: still (on a table) or demo (a 32 s performance). |

Example: `{'source': 'auto'}`

Example: `{'source': 'twin', 'scene': 'demo'}`

### `disconnect`

Let go of the board (its streams stop) or stop the twin.

### `status`

Where the rig stands: the source (board, twin or none), the board, stream rates and drops, recording, OSC, and the latest state in short.

Example: `{}`

### `stream`

Which of the board's streams run (all four by default). Off saves USB bandwidth.

| argument | type | default | what |
|---|---|---|---|
| `motion` | boolean | None | the raw IMU samples ('r'). |
| `state` | boolean | None | what the controls decided, 50 or 100 times a second ('q'). |
| `screen` | boolean | None | the OLED's frames ('o'). |
| `events` | boolean | None | the gestures as they fire ('e'). |

## hands

### `joy.override`

Stand in for the joystick's ADC (0..4095 each, 2048 is the centre); no arguments ends it. joy.on must be set.

| argument | type | default | what |
|---|---|---|---|
| `x` | integer | None | raw X. |
| `y` | integer | None | raw Y. |

### `key`

Turn and press the encoder, or press REC, from the PC. The board's gesture code sees them as if from the pins.

| argument | type | default | what |
|---|---|---|---|
| `enc` | integer | 0 | detents to turn (negative = left). |
| `enc_down` | boolean | None | press (true) or let go (false) of the encoder. |
| `rec` | boolean | None | press (true) or let go (false) of REC. |
| `tap` | boolean | False | a tap of the encoder (down 120 ms, up). |
| `hold_ms` | integer | 0 | hold the encoder this long, then let go. |
| `press_ms` | integer | 0 | with rec=true: let go of REC after this long (a take of that length). |

Example: `{'enc': 3}`

Example: `{'tap': True}`

Example: `{'hold_ms': 800}`

Example: `{'rec': True}`

## inject

### `inject.gesture` (slow)

Act out a gesture in the board's sensor stream (a synthetic hand: the twin's model, with noise and bias). The board's own motion and gesture code takes it as real. Kinds: still, tilt, steps, sweep, flicks, shake, roll, axes, free.

| argument | type | default | what |
|---|---|---|---|
| `kind` | string | 'still' | the gesture. |
| `secs` | number | 3.0 | how long. |
| `pitch` | number | 0.0 | degrees, nose down + (tilt, sweep end). |
| `roll` | number | 0.0 | degrees, right edge down + (tilt, roll). |
| `amp` | number | 0.0 | the size of flicks (deg) or a shake (g). |
| `seed` | integer | 0 | the noise's seed. |
| `wait` | boolean | False | answer when it is over. |

Example: `{'kind': 'tilt', 'pitch': 30, 'secs': 3}`

Example: `{'kind': 'flicks', 'amp': 20, 'secs': 4}`

Example: `{'kind': 'shake', 'amp': 0.6}`

### `inject.stop`

Stop an injection: the sensor is back within half a second.

### `inject.take` (slow)

Play a recorded hand (a session's raw.txt) back into the board: the same gesture through other tuning, on the real firmware.

| argument | type | default | what |
|---|---|---|---|
| `session` | string | 'last' | the session's name (or a unique part of it, or last). |
| `t0` | number | 0.0 | from this second. |
| `t1` | number | 0.0 | to this second (0: the end). |
| `wait` | boolean | False | answer when it is over. |

## log

### `cmds.tail`

The commands anyone ran (viewer, CLI, OSC, MCP), newest last.

| argument | type | default | what |
|---|---|---|---|
| `n` | integer | 30 | how many. |

### `events.tail`

The gestures that fired, newest last.

| argument | type | default | what |
|---|---|---|---|
| `n` | integer | 30 | how many. |
| `name` | string | '' | only these (a prefix: enc, tilt, roll ...). |

### `log.tail`

The board's log lines (and the rig's notices), newest last.

| argument | type | default | what |
|---|---|---|---|
| `n` | integer | 30 | how many. |
| `level` | string | '' | warn: only warnings. |

## osc

### `osc.config`

Where OSC goes and listens (slrig/osc.py lists the addresses). On by default: 127.0.0.1:9000 out, 9001 in.

| argument | type | default | what |
|---|---|---|---|
| `out_host` | string | '' | the host to send to. |
| `out_port` | integer | 0 | the port to send to. |
| `in_port` | integer | 0 | the port to listen on. |
| `on` | boolean | None | send or not. |

## record

### `record.start`

Start recording everything the board says (motion, state, events, screen) into a session folder.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'take' | a few words for the folder's name. |
| `secs` | number | 0.0 | stop by itself after this long (0: until record.stop). |
| `notes` | string | '' | what you are doing, for later. |

Example: `{'name': 'slow tilts', 'secs': 20}`

### `record.stop`

Stop recording; the session's summary.

## session

### `session.analyze` (slow)

Analyse a session: its guided test's own analysis if it was one, else the general look (rest noise and bias, drift, the gestures that fired). Written to analysis.json.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session. |

### `session.compare` (slow)

The same recorded hand through two tuning sets: the board's angles and speed under each, the numbers side by side (jitter at rest, lag, how far a shake moves the speed), and a plot.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session. |
| `a` | string | 'v1' | the first tuning set (as session.replay's tune). |
| `b` | string | 'gyro' | the second. |
| `plot` | boolean | True | also draw both (a PNG beside the session). |

Example: `{'name': 'last', 'a': 'v1', 'b': 'gyro'}`

### `session.info`

A session's meta (tuning and settings at the time, the test and its steps) and, if analysed, its analysis.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session (a unique part of its name, or last). |

### `session.list`

The recordings, newest first.

| argument | type | default | what |
|---|---|---|---|
| `limit` | integer | 30 | how many. |

### `session.notes`

Add a line to a session's notes (what it felt like, what changed).

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session. |
| `text` | string | '' | the note. |

### `session.plot` (slow)

Draw a session: stacked panels of the chosen fields, gestures along the bottom, test steps shaded. A PNG.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session. |
| `fields` | string | 'acc,gyro,angles,speed' | any of acc, gyro, angles, speed, fx, joy, levels (comma separated). |
| `t0` | number | 0.0 | from this second. |
| `t1` | number | 0.0 | to this second (0: the end). |

### `session.replay` (slow)

Replay a session's raw motion through the firmware's own motion.c and gesture.c (the twin's calculator) with a tuning set, and write replay-<label>.csv: what the board would have done with that tuning.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | 'last' | the session. |
| `tune` | string | 'current' | current, recorded, v1, gyro, gyro detents, mahony, A, B, or a JSON object of name: value. |
| `label` | string | '' | the file's label (default: the set's name). |

Example: `{'name': 'last', 'tune': 'gyro'}`

## settings

### `settings.list`

The board's settings (the menu's), as text: Mode, Tilt, Speed max, ... They are stepped, not set.

### `settings.step`

Step one of the board's settings as the encoder would (an action, such as Save, runs with delta 1).

| argument | type | default | what |
|---|---|---|---|
| `index` | integer | required | the setting's i (settings.list). |
| `delta` | integer | 1 | +1 or -1. |

Example: `{'index': 5, 'delta': 1}`

## test

### `test.abort`

Stop the guided test that is running (its recording is kept, marked aborted).

### `test.list`

The guided tests: what each finds out, and its steps.

### `test.run` (slow)

Run a guided test: the viewer shows each step's prompt with a countdown, the rig records the whole test, then analyses it. On the twin (or with inject=true) the rig acts the steps out itself, so the analysis can be checked without hands.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | required | the test (test.list). |
| `inject` | boolean | None | act the steps out (default: on the twin yes, on a board no). |
| `countdown` | number | 3.0 | seconds of "get ready" before each step. |
| `apply` | boolean | False | set the tuning values the analysis suggests (otherwise they are only reported). |

Example: `{'name': 'still'}`

Example: `{'name': 'steps', 'inject': True}`

## tune

### `tune.ab`

Two whole tuning sets to flip between while listening: store the board's current set in A or B, or recall one.

| argument | type | default | what |
|---|---|---|---|
| `slot` | string | required | A or B. |
| `store` | boolean | False | true keeps the current set there; false (the default) loads it onto the board. |

### `tune.export`

Write the current tuning as JSON and as the C lines that would make it the firmware's defaults (for a review before anyone edits tune.h). Nothing on the board changes.

| argument | type | default | what |
|---|---|---|---|
| `path` | string | '' | where to write the JSON (default: the sessions folder, tune-<time>.json). |

### `tune.get`

One tuning value.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | required | e.g. tilt.dead, motion.fusion, enc.hold. |

### `tune.list`

The tuning table as the board has it: name, kind, range, step, default, value, unit, help.

| argument | type | default | what |
|---|---|---|---|
| `group` | string | '' | only this group (imu, motion, tilt, roll, joy, enc, rec, mic, usb, rig). |
| `changed` | boolean | False | only the values that differ from the defaults (v1). |

### `tune.preset`

Load a preset onto the board: v1 (today's feel), gyro (COMP fusion at 100 Hz), gyro detents, mahony.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | required | v1, gyro, gyro detents or mahony (or its number). |

Example: `{'name': 'gyro'}`

### `tune.reset`

All tuning values back to the defaults: the firmware as it was before the table (v1). Not saved.

### `tune.save`

Keep the board's current tuning in its flash (NVS "tune"), for the next power-on.

### `tune.set`

Change a tuning value on the board, at once (not saved until tune.save). Enums take their label or index; an action runs with any value.

| argument | type | default | what |
|---|---|---|---|
| `name` | string | required | the value's name (tune.list). |
| `value` | string | required | a number, or an enum's label (e.g. COMP, "8 g", 500). |

Example: `{'name': 'tilt.dead', 'value': 6.5}`

Example: `{'name': 'motion.fusion', 'value': 'COMP'}`

## util

### `help`

The commands: with no topic, every name and its one-line summary by group; with a command's name, its arguments as JSON Schema and examples; with a group's name, its commands.

| argument | type | default | what |
|---|---|---|---|
| `topic` | string | '' | a command, a group, or nothing. |

### `wait` (slow)

Do nothing for a while (between steps of a batch).

| argument | type | default | what |
|---|---|---|---|
| `secs` | number | 1.0 | how long. |

## view

### `curve`

The tilt-to-speed curve and the roll-to-effects curves as the firmware's own gesture.c computes them with the board's current tuning and Speed min/max (the twin's calculator).

| argument | type | default | what |
|---|---|---|---|
| `n` | integer | 121 | points from -90 to +90 degrees. |

### `gestures`

Every gesture the board knows: its rule in words with the current numbers, the tuning values behind it, how often it fired since the rig connected and when last.

### `motion.snapshot`

The motion of the last moments in numbers: the latest sample, means and spreads over the window (device axes), the board's angles and the host's reference orientation.

| argument | type | default | what |
|---|---|---|---|
| `secs` | number | 1.0 | the window. |

### `screen.png`

The board's screen right now as a PNG (the OLED's pixels, the two-colour panel's tint).

| argument | type | default | what |
|---|---|---|---|
| `scale` | integer | 4 | pixels per OLED pixel. |
| `path` | string | '' | where (default: the run folder). |

### `view.shot` (slow)

A picture of the viewer (the 3D board, the screen, the plots, the panels) rendered offscreen: no window opens.

| argument | type | default | what |
|---|---|---|---|
| `width` | integer | 1600 | pixels. |
| `height` | integer | 1000 | pixels. |
| `tab` | string | '' | tune, gestures, settings or session. |
| `path` | string | '' | where (default: the run folder). |
